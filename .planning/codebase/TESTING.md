# Testing Patterns

**Analysis Date:** 2026-01-26

## Test Framework

**Status:** No automated unit test framework configured

**Runner:**
- `npm test` returns "No tests found" (echo command in package.json)
- No Jest, Vitest, or other unit test runner installed
- No `.test.ts` or `.spec.ts` files in source code (only in node_modules)

**Custom Test Scripts:**
- Located: `scripts/` directory
- Use direct TypeScript execution via `tsx` or `node bin/run.js`
- Implement custom Logger interface for test output

**Run Commands:**
```bash
npm run test-custom-calcs              # Test BIM → SML conversion with validation
npm run test-conversion                # Batch BIM conversion with summary report
npm run validate-conversion            # Single file validation with detailed output
npm run deploy-test                    # Test deployment validation
```

## Test File Organization

**Location Pattern:**
- Test scripts in `scripts/` directory, not co-located with source
- Source files in `src/commands/` and `src/shared/`
- Test data in `test-files/` directory (BIM sample files)
- Results written to JSON files: `*test-results.json`

**Script Files:**
- `scripts/test-custom-calcs.ts` - Main validation testing
- `scripts/test-bim-conversion.ts` - Batch testing with regression detection
- `scripts/validate-bim-conversion.ts` - Detailed single-file validation
- `scripts/deploy-test.ts` - Deployment-specific testing
- All scripts use `#!/usr/bin/env tsx` shebang

## Test Structure

**Pattern: Custom Logger Implementation**

Every test script implements the `Logger` interface with conditional output:

```typescript
class TestLogger implements Logger {
  constructor(private isVerbose: boolean = false) {}

  error(message: string) {
    console.error(`[ERROR] ${message}`);
  }
  warn(message: string) {
    if (this.isVerbose) console.warn(`[WARN] ${message}`);
  }
  info(message: string) {
    if (this.isVerbose) console.log(`[INFO] ${message}`);
  }
  http(message: string) {
    if (this.isVerbose) console.log(`[HTTP] ${message}`);
  }
  verbose(message: string) {
    if (this.isVerbose) console.log(`[VERBOSE] ${message}`);
  }
  debug(message: string) {
    if (this.isVerbose) console.log(`[DEBUG] ${message}`);
  }
  silly(message: string) {
    if (this.isVerbose) console.log(`[SILLY] ${message}`);
  }
}
```

**Test Execution Pattern:**

```typescript
// 1. Parse arguments
const args = process.argv.slice(2);
const inputFile = args.find(arg => arg.includes("--input"));

// 2. Initialize components
const logger = new TestLogger(verbose);
const parser = new BimFileParser();

// 3. Execute conversion
const startTime = Date.now();
const smlResult = await converter.convert(bimParsed);

// 4. Validate and report
const validation = await validateConversion(smlResult);
```

## Mocking

**Framework:** No mocking library (Jest, Sinon, etc.)

**Patterns Used:**

**1. Custom Logger Mock:**
- Implement `Logger` interface directly in test
- Control output verbosity for cleaner test output
- No spy/assertion on logger calls - only output verification

**2. Test Data Fixtures:**
- BIM files in `test-files/` directory
  - `test-files/dw_test_model.bim` - default test file
  - `test-files/pbi_dw_test_model.bim` - Power BI model example
- JSON result files for baseline comparison
  - `baseline.json` - reference results
  - `diff.json` - differences from baseline (generated by test script)

**3. In-Memory Object Construction:**
- No mocking of file I/O - actual file system used
- Direct instantiation of converters with test logger
- Build real `SmlConverterResult` objects and validate

**What to Mock:**
- Logger implementation (always required)
- File paths (use test-files directory)

**What NOT to Mock:**
- Converters - test actual conversion logic
- File I/O - use test-files directory with real files
- SML object construction - validate actual output

## Test Types

**1. Integration Tests (Primary)**
- **Scope:** End-to-end conversion from BIM/DBT to SML
- **Approach:** Load actual files, run full converter pipeline, validate output
- **Location:** `scripts/test-custom-calcs.ts`, `scripts/test-bim-conversion.ts`
- **Example:** Convert BIM file, write to disk, validate YAML structure

**2. Regression Tests**
- **Scope:** Detect unexpected changes in conversion output
- **Approach:** Compare current results against baseline JSON
- **Location:** `scripts/test-bim-conversion.ts` with `--baseline` flag
- **Command:**
  ```bash
  npm run test-conversion -- --input ./test-bim --baseline baseline.json --diff diff.json
  ```
- **Output:** JSON diff showing what changed

**3. Validation Tests**
- **Scope:** Check output structure and validity
- **Approach:** Parse generated SML YAML, validate against schema
- **Location:** `scripts/validate-bim-conversion.ts`
- **Checks:**
  - YAML parses without error
  - Required SML fields present
  - Objects have valid `unique_name` values

**4. Deployment Tests**
- **Scope:** Snowflake Cortex Analyst specific validation
- **Approach:** Convert SML → Cortex YAML, validate schema
- **Location:** `scripts/deploy-test.ts`
- **Runs:** `npm run deploy-test`

**E2E Tests:** Not implemented as separate suite - integration tests serve this role

## Common Patterns

**Async/Await Pattern:**

```typescript
async function testConversion() {
  try {
    const smlResult = await converter.convert(parsed);
    const validation = await validateConversion(smlResult);
    console.log(validation);
  } catch (error) {
    console.error(`Test failed: ${error}`);
    process.exit(1);
  }
}

testConversion();
```

**Error Testing:**
- Catch errors from converters
- Log error details
- Exit with code 1 on failure
- No try-catch assertions (no framework)

```typescript
try {
  await converter.convert(invalidInput);
} catch (error) {
  console.error(`Expected error: ${error.message}`);
}
```

**Result Reporting Pattern:**

Tests output JSON or structured text:

```typescript
interface ConversionResult {
  success: boolean;
  file: string;
  duration_ms: number;
  counts: { models: number; datasets: number; /* ... */ };
  error?: string;
}

const result: ConversionResult = {
  success: validation.success,
  file: inputFile,
  duration_ms,
  counts: { /* extracted from smlResult */ },
};

console.log(JSON.stringify(result, null, 2));
```

## Test Execution Best Practices

**Command Running:**
```bash
# Use npm scripts - no direct tsx in production
npm run test-custom-calcs

# Pass arguments
npm run test-custom-calcs -- --input ./path/to/file.bim

# Check verbose output
npm run test-custom-calcs -- --verbose
```

**Default Test File:**
- `test-files/dw_test_model.bim` used if no `--input` specified
- Ensures tests run without configuration

**Validation Workflow:**

1. Run test: `npm run test-custom-calcs`
2. Review summary output (models, dimensions, metrics counts)
3. Check TODO breakdown (unconvertible expressions by category)
4. Examine SML output directory for YAML files
5. For regression: compare against baseline: `npm run test-conversion -- --baseline baseline.json`

## Manual Testing Guidelines

**For BIM Conversions:**
```bash
# Convert single BIM file with validation
npm run test-custom-calcs -- --input ./my-model.bim --verbose

# Batch test with regression detection
npm run test-conversion -- --input ./bim-models --baseline prev_results.json

# Validate Cortex output
npm run deploy-test
```

**For DAX Conversion:**
- Enable AI conversion: add `--llmName openai` or `--llmName anthropic`
- Requires env vars: `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`
- Check `metric_calc_details.ai_conversion` count in results

**Inspection:**
- YAML files written to `sml_output/` subdirectories
- Use `npm run lint` to check syntax
- Manual review for semantic correctness
