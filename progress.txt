# Progress Log

## Learnings

- Dimensions have unique_name like `dimension.{tableName}` and hierarchies like `{tableName} Hierarchy`
- Use makeUniqueName() to generate proper SML unique names
- ConversionContext provides access to result.dimensions for lookups
- Templates use result via ConversionContext for cross-object resolution

---

## Iteration 1 - US-001: Dimension Column Reference Resolution
- Implemented resolveDimensionHierarchy() in converter-utils.ts
- Resolution strategy: 1) lookup by dim.label, 2) lookup by level_attribute.dataset, 3) fallback to convention
- Files changed: src/commands/bim-to-sml/bim-converter/converter-utils.ts
- Learnings:
  - Dimensions created with label = bimTable.name, unique_name = dimension.{tableName}
  - Hierarchies have unique_name = {tableName} Hierarchy (with makeUniqueName)
  - Level attributes have dataset = dataset.{tableName}

## Iteration 11 - US-007: PARALLELPERIOD Template
- Implemented ParallelPeriodTemplate in parallelperiod-template.ts
- Converts CALCULATE([measure], PARALLELPERIOD(Table[DateCol], -1, YEAR)) to (ParallelPeriod([dim].[hier].[Year], 1, [dim].[hier].CurrentMember), [Measures].[measure])
- Files changed:
  - src/commands/bim-to-sml/bim-converter/conversion-templates/templates/parallelperiod-template.ts (new)
  - src/commands/bim-to-sml/bim-converter/conversion-templates/template-registry.ts
- Learnings:
  - PARALLELPERIOD takes 3 args: date column, offset, interval (YEAR/QUARTER/MONTH/DAY)
  - DAX negative offset (-1) means "go back in time"; MDX positive offset (1) means same
  - Used LiteralToken for numeric values, OperatorToken for "-", IdentifierToken for interval names
  - PARALLELPERIOD was already in function-mappings.json complex_patterns
  - Measure "Sales Parallel Period LY" already existed in model.bim
  - Conversion rate: 63% (43/68 converted)

## Iteration 13 - US-009: DATEADD Template
- Implemented DateAddTemplate in dateadd-template.ts
- Converts CALCULATE([measure], DATEADD(Table[DateCol], offset, interval)) to MDX Lag/Lead pattern
- Negative offset in DAX (go back in time) maps to Lag() in MDX
- Positive offset in DAX (go forward in time) maps to Lead() in MDX
- Files changed (in sml-converters repo):
