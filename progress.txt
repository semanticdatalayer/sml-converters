## Iteration 7 - US-007: Create IN operator template
- Created `InOperatorTemplate` class in `conversion-templates/templates/in-operator-template.ts`
- Handles standalone `column IN { val1, val2, ... }` patterns
- Single-value sets simplified to direct equality: `col = "a"`
- Multi-value sets convert to: `IIF(col = "val1" OR col = "val2" OR ..., 1, 0)`
- Empty sets and non-literal values return TODO failures (edge cases)
- Uses `extractValues()` helper to parse BraceToken contents
- Handles LiteralToken for strings/numbers, IdentifierToken for TRUE/FALSE
- Confidence: 0.95
- Files changed:
  - src/commands/bim-to-sml/bim-converter/conversion-templates/templates/in-operator-template.ts (new file, ~210 lines)
- Learnings:
  - IN can be parsed as OperatorToken or IdentifierToken, check both
  - BraceToken.args contains CommaToken between values - skip them during extraction
  - CalculateTemplate already has IN handling for filter context (US-008 may be done)
  - Template not yet registered in TemplateRegistry (US-010)

## Iteration 9 - US-009: Handle NOT IN operator conversion
- Added NOT IN support to both InOperatorTemplate and CalculateTemplate
- Pattern: `NOT ( col IN { val1, val2 } )` → `IIF(col <> val1 AND col <> val2, 1, 0)`
- InOperatorTemplate: added `detectNotInPattern()` method and refactored `convert()` to handle negation
- CalculateTemplate: added `detectNotInPattern()` and `convertNotInFilter()` methods
- Single-value NOT IN simplified to `col <> val`
- Files changed:
  - src/commands/bim-to-sml/bim-converter/conversion-templates/templates/in-operator-template.ts (+~60 lines)
  - src/commands/bim-to-sml/bim-converter/conversion-templates/templates/calculate-template.ts (+~90 lines)
- Learnings:
  - NOT is parsed as IdentifierToken, parentheses as ParenToken
  - ParenToken.args contains the inner IN expression tokens
  - NOT IN in CALCULATE produces `(col <> a AND col <> b)` without IIF wrapper (filter context)
  - Standalone NOT IN produces `IIF(col <> a AND col <> b, 1, 0)`

## Iteration 14 - US-014: Fix validation errors in MOL conversion
- Fixed 27 validation errors (Type 1: 13 invalid expression, Type 2: 14 non-existing metric)
- **Type 1 Fix**: Move single-line comment removal (// and --) to `expressionAsString()` BEFORE whitespace collapse
  - Problem: `expressionAsString()` joins array with \n then replaces all \s+ with space
  - `removeComments()` then saw single-line expressions and removed everything after // or --
  - Solution: Remove // and -- comments while newlines are intact in `expressionAsString()`
- **Type 2 Fix**: Throw errors instead of returning invalid [Measures].[name] references
  - `TableReference.toMdx()`: Throw if measure creation fails (table unused/dimension-only)
  - `ColumnReference.toMdx()`: Throw if measure/metric not found
  - These errors get caught by pipeline and create proper TODO fallbacks
- Files changed:
  - src/commands/bim-to-sml/bim-converter/tools.ts (expressionAsString, removeComments)
  - src/commands/bim-to-sml/bim-converter/conversion-pipeline.ts (escapeForComment import)
  - src/commands/bim-to-sml/bim-converter/dax-converter.ts (TableReference, ColumnReference toMdx)
- Learnings:
  - DAX expressions in BIM are often arrays where each line is an element
  - Comments with // or -- need removal BEFORE joining with spaces
  - Tables without relationships are in unusedTables and can't have metrics created
  - When conversion can't produce valid MDX, throw error to trigger TODO fallback
