# Progress Log

## Learnings

- Dimensions have unique_name like `dimension.{tableName}` and hierarchies like `{tableName} Hierarchy`
- Use makeUniqueName() to generate proper SML unique names
- ConversionContext provides access to result.dimensions for lookups
- Templates use result via ConversionContext for cross-object resolution

---

## Iteration 1 - US-001: Dimension Column Reference Resolution
- Implemented resolveDimensionHierarchy() in converter-utils.ts
- Resolution strategy: 1) lookup by dim.label, 2) lookup by level_attribute.dataset, 3) fallback to convention
- Files changed: src/commands/bim-to-sml/bim-converter/converter-utils.ts
- Learnings:
  - Dimensions created with label = bimTable.name, unique_name = dimension.{tableName}
  - Hierarchies have unique_name = {tableName} Hierarchy (with makeUniqueName)
  - Level attributes have dataset = dataset.{tableName}

## Iteration 2 - US-002: TOTALYTD Template
- Implemented TotalYtdTemplate in totalytd-template.ts
- Converts TOTALYTD([measure], Table[DateCol]) to Sum(YTD([dim].[hier].CurrentMember), [Measures].[measure])
- Files changed:
  - src/commands/bim-to-sml/bim-converter/conversion-templates/templates/totalytd-template.ts (new)
  - src/commands/bim-to-sml/bim-converter/conversion-templates/template-registry.ts
  - src/commands/bim-to-sml/bim-converter/conversion-pipeline.ts (fix Stage 1 to skip complex patterns)
- Learnings:
  - Stage 1 (direct conversion) was trying to convert ALL function args before checking templates
  - This caused dimension column refs to throw before templates could handle them
  - Fix: Skip complex pattern functions in Stage 1 to let Stage 3 templates handle them
  - resolveDimensionHierarchy() works correctly for mapping TableColumnReference to MDX hierarchy ref
